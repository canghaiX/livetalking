# 铁科院大屏数字人：素材方案与即梦提示词

## 先明确当前模型能做什么

当前部署使用 Wav2Lip：音频驱动口型；表情、头部和肢体动作主要来自输入视频。LLM 标签可以用于选择动作素材，但不会直接让 Wav2Lip 生成新的肢体动作。

官方文档的 `customvideo_config` 与 `/set_audiotype` 支持播放预制片段。当前代码 `avatars/base_avatar.py` 在自定义片段分支直接读取整帧，跳过口型贴回；`avatars/audio_features/base_asr.py` 会优先播放自定义片段的音频。因此该接口适合欢迎、待机、转场、固定致意，不适合直接叠加任意实时 TTS。当前实现的 `audiotype>=2` 还需要 `audiopath`；没有声音的片段可准备同长的 16kHz 单声道静音 WAV。

要实现“任意讲解文本 + 微笑/严肃/手势”，需将每段视频各自制作成 Wav2Lip avatar（`full_imgs`、`face_imgs`、`coords.pkl`）。当前部署已实现同一会话内的情绪与手势调度，普通讲解以微笑为主，伸手和致谢单次播放；播放范围与时序见 `deployment/avatar_motion.json` 和 [角色包说明](avatar_packages.md)。`/offer` 显式选择 avatar 时保留独立动作预览。TTS 参数不等同于视觉表情参数。微笑等嘴部表情可能被口型推理覆盖，宜依靠眼神、眉毛、面颊和姿态表达。

图片可以用于确定人物身份或做静态待机；仅准备几张表情图不能得到自然连续的动作。对本项目更适合“人物定稿图 → 同一参考图生成多段视频 → 素材审核 → avatar 预处理 → 调度”。即梦只是素材来源，也可以实拍或用 3D 渲染。

## 推荐素材清单

| 素材标签 | 场景 | 建议 |
|---|---|---|
| neutral_explain | 常规技术讲解 | 稳定默认状态，最高优先级 |
| welcome_smile | 开场欢迎 | 亲切微笑，轻点头 |
| serious_emphasis | 安全、可靠性、核心指标 | 神情专注，不皱眉发怒 |
| guide_screen_left | 引导观看屏幕内容 | 开掌引导，避免遮脸 |
| proud_achievement | 展示科研成果 | 克制自信，小幅手势 |
| listening | 等待提问 | 轻微呼吸、自然眨眼 |
| mild_surprise | 趣味科普或对比 | 轻抬眉；通常无需高频使用 |
| closing_thanks | 总结致谢 | 微笑点头，回到站姿 |

一期先做 neutral_explain、welcome_smile、serious_emphasis、guide_screen_left、closing_thanks 五段。每段一个动作，先用 5–8 秒短片测试，再按实际循环效果调整时长。建议动作从中性姿态开始并回到同一中性姿态，但生成结果不保证无缝循环，需要剪辑审核。当前程序有往返播放帧的逻辑，应特别检查反向播放时的动作是否自然。

## 所有视频共用的前缀

> 以提供的人物定稿图为唯一角色参考，保持同一张脸、年龄、发型、服装、肤色、身材比例和背景。固定机位，固定焦距，固定光照，正面腰部以上中景，人物位置和大小不变，双手完整入画。人物不说话，嘴唇自然轻合，口周保持放松，呼吸和眨眼自然。头部保持接近正面，所有动作小幅、缓慢、克制，适合铁路科研展厅的正式讲解。动作从参考图的中性站姿开始，结束时自然回到同一中性站姿。

逐条追加下面的动作后缀；不要在一段视频里合并多种动作。

### 1. 中性讲解

> 人物保持专业平和的神情，视线稳定地面向镜头，自然眨眼一次，胸肩有细微自然呼吸。双手保持腰前放松姿态，做一次极小幅度的自然点头，然后回到最初站姿。全程没有夸张表情和明显身体位移。

### 2. 微笑欢迎

> 人物从中性神情缓慢转为温和的闭嘴微笑，眼神亲切，面颊轻微抬起，轻轻点头一次表达欢迎。双手仍保持腰前自然姿态，动作结束后缓慢回到初始神情。微笑克制，不露齿，不大笑，不挥手。

### 3. 严肃强调

> 人物的眼神变得专注、坚定，眉部轻微收敛，嘴角放松，呈现解释科研数据和强调运行安全时的认真神情。做一次轻微而稳重的点头，肩膀和双手保持稳定，随后回到中性站姿。不生气、不瞪眼、不紧锁眉头。

### 4. 引导观看屏幕左侧

> 人物保持正面朝向镜头，将画面左侧的手缓慢抬至胸部以下，五指自然并拢，掌心向上，朝画面左侧做一个简洁的展示引导手势，短暂停留，再缓慢收回腰前。脸部始终接近正面，手不遮挡脸部，身体不转身，动作结束回到起始姿态。

角色放在大屏右侧时使用此版本；放在左侧则统一替换成“画面右侧”。以最终生成画面检查方向，避免依赖左右手称谓。

### 5. 展示科研成果

> 人物呈现沉稳、自信、轻微欣慰的闭嘴微笑，眼神有精神。腰前的一只手小幅向外打开，掌心向上，表达展示成果和介绍亮点，短暂停顿后将手收回原位，神情回到自然平和。不欢呼、不鼓掌、不握拳。

### 6. 倾听等待

> 人物保持友好安静的闭嘴神情，视线面向镜头，眉部略微放松，自然眨眼一次，头部只有极轻微的倾斜并恢复，呈现耐心倾听参观者问题的状态。双手保持腰前放松姿态，身体稳定，只有轻微呼吸。

### 7. 克制惊讶

> 人物的眉毛短暂轻轻抬起，眼神稍微明亮，表现对有趣科研事实的轻微惊讶与兴趣，随后自然恢复平和神情。嘴唇始终轻合，不张嘴，不瞪大眼睛，不后仰，不耸肩，不表现恐惧，动作幅度很小。

### 8. 总结致谢

> 人物保持温和闭嘴微笑，双手自然停在腰前，轻轻点头一次表达感谢，保持片刻，再缓慢回到中性站姿。肩颈放松，视线稳定面向镜头，不深鞠躬，不转身，不挥舞手臂。

### 新素材生成与交接

- 建议每段 5–8 秒；循环素材保证有足够长的稳定段，单次动作保证开头和结尾各约 0.5–1 秒站姿，不为凑时长重复动作。
- 输出分辨率、人物大小、背景和光照与当前角色一致。帧率需检查并准备为恒定 25fps；提示词中的帧率或时长描述不能保证实际文件符合要求。
- 不合格的换脸、手指变形、衣服闪烁、背景变化、明显低头或动作未收回需要重做，不能依靠解析修复。
- 这四个素材 ID 是新增建议，不会因上传就自动获得新的触发规则。解析后还需绑定角色包，并配置稳定帧范围、单次播放方式和触发场景；已发布素材不能直接覆盖，替换时需创建新角色包。
- 当前自动调度只实现微笑、严肃、伸手和致谢；点头确认及小幅强调需在接入新素材时扩展调度。

## 通用排除描述

若工具提供负向提示框，可放入该框；否则作为正文约束追加。提示词只能提高符合要求的概率，不能替代素材检查。

> 不换脸，不改变发型服装，不改变背景和光照，不移动镜头，不推拉变焦，不旋转镜头，不切换景别，不走动，不转身，不侧脸，不遮挡嘴部，不用手触碰脸部，不张嘴说话，不露齿大笑，不做夸张表情，不出现多余手指或手部变形，不裁断手，不出现面部抖动、服装闪烁、画面闪烁，不生成文字、字幕、标志、水印或第二个人物。

## 转为 LiveTalking 素材时的检查

1. 检查身份一致、手部、边缘、面部是否变形；不合格片段重新生成。
2. 所有片段统一分辨率、构图、背景、曝光，转换为 25fps；生成工具实际输出帧率应以文件检测结果为准。
3. 面部应清晰且占有足够像素；当前 wav2lip256 模型的脸部裁剪为 256×256，4K 原视频不意味着模型生成的口型也是原生 4K。
4. Wav2Lip avatar 制作使用 `python -m avatars.wav2lip.genavatar --video_path ... --avatar_id ... --img_size 256`，需要人脸检测模型可用。每个动作独立生成匹配的完整帧、脸部帧和坐标，不能只替换视频文件。
5. 动态讲解素材的嘴部保持自然闭合，避免源视频的说话口型与新音频冲突；保持正面，避免大幅转头和手遮脸。
6. 对讲解类素材，按段落或句子边界调度，避免逐词切换。首先保证动作的起止姿态一致，再考虑过渡；简单淡入淡出可能产生双脸，不应视为天然解决办法。

## 当前 LLM 输出与新增素材接入

```json
{
  "segments": [
    {
      "text": "接下来，请看屏幕展示的试验平台。",
      "emotion": "neutral",
      "gesture": "introduce"
    }
  ]
}
```

当前调度层接受白名单 emotion/gesture，并在播报段落边界选择已准备素材。普通情绪对应微笑，未知情绪按 neutral 处理，未知手势按 none 处理；伸手同轮最多一次、间隔至少 30 秒。通常讲解脚本按段落预先编排比自动情绪判断更可控；LLM 适合用于互动问答补充。新增素材需进一步明确对应状态与触发规则，不直接把素材文件名作为可执行标签交给 LLM。
